# D-387 — Hot-path performance remediation (the 2026-09-18 external performance review)

## Status

RATIFIED

## Context

An external performance review of the packaged tree (`vivim-omega-latest`, reviewed at
4cf5283) examined the hot paths — port router, vault/SQLite layer, boot/verify, web
console live streams, watchdog, discovery/mind engines — and filed nine findings with
a priority order. The review's own TL;DR credits the codebase with unusual
performance literacy (D-378's measured fixes, D-363's event-driven boot readiness,
D-330's compile cache) and frames the gaps as "the same discipline not yet applied"
to specific paths, not sloppy code. Every finding was verified against the tree
before any code moved; all nine held as stated, with two (CAS fsync durability,
boot-verify rehash) explicitly acknowledged by the review itself as deliberate
tradeoffs. This record implements the review's priority list under the repo's own
evidence law: measure first, falsify behavior, defer what has no trigger, and revert
what does not survive measurement.

## Options

| Criterion | (a) Implement per the review's priority order, measured | (b) Land everything including the "easy wins" | (c) Defer all to Wave lanes |
|---|---|---|---|
| Blast radius | #1 (uncapped N+1 every 500ms forever) closed now | Same, plus unmeasured micro-changes in durability/verify law | The highest-impact path keeps burning CPU/I/O on every console |
| Risk | Each change carries a behavior-pinning falsifier; measured deltas archived | Unverified micro-edits to B1-adjacent code (verify rehash) | Wave lanes own features, not review remediation — the review ages badly |
| Honesty | Two recommendations measured and REJECTED (json_extract prefilter) or DEFERRED with named triggers (test-only hash cache, batch-append fsync) | Rubber-stamping the review without running its ideas past the harness | Silent non-action contradicts the daily loop |

## Decision

**Decision:** (a) — implement findings #1, #2, #4, #5, #6, #9; measure-and-reject the
#3 prefilter attempt; defer #7 and #8 with named triggers.

1. **#1 world-poll (HIGH) — the console's live stream stops reading the vault blind.**
   New `vault.getmany@1` (READ contract, grammar-lowercase per the SDK law):
   `readObjects()` resolves latest-rev-per-id with the exact hot→cold order of
   `vault.get@1`; a missing id is DATA (`{found:false}`), a malformed envelope still
   THROWS (corruption must not masquerade as absence), a missing CAS blob still
   throws, duplicates collapse, >512 distinct ids refuse. `vivim.mind` swaps its
   per-row `vault.get@1` loop for ONE `getmany` hop per namespace and runs its four
   evidence reads in parallel through `allEvidence()` — a Promise.all that observes
   every rejection so a lost race against compartment shutdown can never surface as
   an unhandled error; the first failure in order still throws (fail-closed
   unchanged). The web poll is GATED on connected sockets (zero watchers → zero
   vault reads), version-checks through a bodiless snapshot
   (`mind.snapshot@1 {includeBodies:false}` — v is evidence-count-derived, so the
   light call detects identical bumps), and pays for the full payload only when the
   version actually changed; the baseline observation records from the light call.
   Manifest/composition surface: vault contributes the contract, mind requests
   `port:vault.getmany@1` (dropping the now-unused `port:vault.get@1` — the lens
   requests exactly what it uses), console.json routes + grants it, matrix
   regenerated byte-identical.
2. **#2 compaction FTS delete (MEDIUM-HIGH) — D-378's discipline applied to the
   delete path.** `ftsDeleteMany()` stages the moved (id, rev) triples into a temp
   table and removes all their FTS rows in ONE scan inside the same transaction;
   the per-candidate move loop keeps its PK-indexed INSERT/DELETE and only collects
   triples. Measured 782.1 → 17.97 ms at 2,000 candidates (~43×), zero FTS orphans
   pinned by falsifier. `ftsDelete` remains for single-row callers.
3. **#4 verify batching (MEDIUM) — set-based, identical verdicts.** Step 2 becomes
   one `NOT EXISTS`-paired probe over both PKs (`ORDER BY seq LIMIT 1` keeps
   lowest-seq-first divergence reporting). Step 3 fetches DISTINCT cids in one
   statement and stats each distinct blob once; the missing-CAS carrier resolves
   through a rare-path query (corruption path only — no hot-path cost). A nuance is
   accepted and documented: when SEVERAL blobs are missing, the reported corruptAt
   is the lowest changelog seq among them (the old scan order was ns/id/rev, not
   seq — neither was seq-ordered; single-missing verdicts are byte-identical).
4. **#5 journal history (MEDIUM) — bounded backward read.** `journalHistory`
   reads the file END-BACKWARD in 16KB chunks (buffer-level concat, so a chunk
   boundary can never split a UTF-8 char), stopping once >maxLines newlines are
   held; cost tracks what is shown, not the journal's lifetime size. Measured
   8.56 → 1.08 ms at a 5.7MB journal — and the old cost grew linearly with the
   journal forever (it is never rotated), the new one is flat.
5. **#6 sync FS polling (LOW-MEDIUM) — async pump.** The 250ms tail pump uses
   `fs.promises` (stat/open/read/close) with an in-flight guard against tick
   overlap; no synchronous filesystem call blocks the event loop on a tick.
6. **#9 policy table (LOW) — precomputed, differential-proven.** `classifyRisk`
   builds a WeakMap-cached index per policy doc (exact rows first-wins in a Map;
   prefix rows sorted longest-first ONCE, stable for equal lengths). Amendment
   safety holds because policy is DATA replaced by reference (ShadowAmendment
   clones) — a replaced doc recompiles; a mutated doc is impossible by construction.
   A differential falsifier keeps the shipped policy, a reversed table, duplicate
   exact rows, and overlapping/equal-length prefix families in lockstep with the
   review-era algorithm (D-351 exact-outranks-prefix and D-384 specificity pinned).
7. **#3 liveRefs (MEDIUM) — implemented, MEASURED, REVERTED.** The SQL
   `json_extract` prefilter (skip JS parse for ref-less rows) was landed and then
   measured WORSE than the plain scan (3.8–7.1 ms vs 3.2–3.9 ms per 5,000 objects —
   SQLite's per-row json_extract overhead exceeds V8's JSON.parse at these envelope
   sizes). Reverted per the measured-not-assumed law; the review's actual
   recommendation (a reverse-reference index) remains a NAMED DEFERRAL below.
8. **#7 CAS fsync batching (LOW) — DEFERRED, named trigger.** The review itself
   marks this "no change needed for correctness-sensitive paths"; the two-fsync
   write-tmp-rename boundary IS the durability law (B4). Trigger: a bulk-import
   requirement (≥1k objects per call) materializes in a wave spec → an explicit
   `vault.appendMany` with a DISTINCT, documented durability guarantee gets its own
   evidence-class record.
9. **#8 test-only hash cache (LOW) — DEFERRED, named trigger.** Boot-verify's
   re-derivation-from-bytes is B1's fail-closed property and the adversarial tests'
   tamper-refusal subject; caching the verify half would weaken what the suite
   proves for a few seconds of wall time (the compile half alone is small — plugin
   trees are tiny). Trigger: the Budget watch's suite wall-time line (recheck near
   ~1,000 tests) flags `bun test` as a cost item → a test-only mtime cache limited
   to the COMPILE path lands with its own record.

## Consequences

- The console's steady-state cost model changes: zero watchers → zero poll reads;
  one watcher + no change → 4 parallel light evidence reads (2 port hops per
  namespace instead of 201); a version bump → one full snapshot for the emit. The
  `vault.get@1` op is unchanged and remains generally available — only the mind's
  internal window read moved to the batch.
- `vault.getmany@1` is a READ contract routed in the 11 compositions that route the
  vault family; the parity net is unaffected (READ ops never gate).
- verify()'s verdicts are pinned as behavior (dangling revision → lowest seq;
  missing CAS → link seq; healthy → green), not as implementation; the driver
  conformance workload (append → verify → search → roundtrip → compaction on BOTH
  drivers) exercises the new SQL cross-runtime for free.
- Two named deferrals (#7, #8) and one measured rejection (#3 prefilter) are
  recorded HERE so the next auditor starts from this line; the reverse-reference
  index joins the postgres driver and the wasm tier in the deferral registry with
  its own trigger (compaction running periodically against multi-GB vaults).
- BENCHMARKS.md culture: the measurement harness (`tooling/perf/perf-remediation.ts`)
  is a repo artifact — the before/after table in the evidence file is reproducible
  by running it on any checkout.
