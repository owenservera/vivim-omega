# D-426 — The falsifier-first loop: omega:loop stub generation + coverage audit

## Status

RATIFIED

## Context

- Records NAME falsifiers in their Evidence sections, but the link from
  declaration to executable is convention only: nothing generates the RED
  stub when a record lands, nothing audits that every declared named
  falsifier resolves to a test file, and nothing stops a regeneration from
  clobbering an implemented test.
- The gap is the verification loop's weakest joint: an agent implementing
  a record must first invent its test file's shape, then hope the test it
  writes actually encodes the clauses the record declared. Interpretation
  loss, exactly the class the genome (D-425) exists to kill, survived one
  more hop.
- Two falsifier conventions now coexist and must not be conflated: the
  record-local F-1..F-5 numbering (D-423, D-424) and the named ALL-CAPS
  ids this family introduces (F-GENOME, F-LOOP, …). The named convention
  is the loop's scope; the local convention predates it and stays valid.

Blocks: none

## Options

| Criterion | (a) omega:loop — deterministic stub generation + tree-wide coverage audit, refusing to clobber implemented files | (b) Fold stub generation into omega:new-decision only | (c) Keep the convention manual |
|---|---|---|---|
| Red-first is mechanical | Yes — the stub throws per declared clause until implemented; done-ness becomes "the falsifier is green" | Partially — scaffolds get stubs, but records amended after scaffold and the audit have no path | No |
| Never clobbers evidence | Yes — LOOP_STUB_OVERWRITE refuses unless --force | Riskier — scaffold-time generation invites re-runs over implemented files | Unenforced |
| Coverage is auditable | Yes — --status lists every named falsifier → test file, RED on unresolved | No | No |
| One parser, no drift | Yes — clause extraction comes from genome.ts (extractNamedFalsifiers); this tool adds zero second parsers | Would duplicate extraction at scaffold time | N/A |
| Zero host LOC | Yes — tooling only | Yes | Yes |

## Decision

**Decision:** (a) — `tooling/gates/loopstub.ts`, in substance:

- **Extraction** reuses `extractNamedFalsifiers` from genome.ts (D-425):
  Evidence lines shaped `- F-XXX.N (clause-title) — …` declare id, clause
  number, and title. An id mentioned in prose but never in a clause line
  surfaces as a clause-less declaration so the audit bites.
- **Stub generation** (`omega:loop --stub D-NNN`) writes
  `tooling/gates/test/f-<id>.test.ts` — one RED test per declared clause,
  each throwing "not implemented", bytes a pure function of the record
  text. The stub IS the falsifier file: the agent fills in the verdicts,
  keeps the ids, makes the gate run them green.
- **No clobber**: regenerating over a file that is no longer the stub
  template refuses LOOP_STUB_OVERWRITE — an implemented falsifier is
  evidence, and evidence is never silently overwritten. `--force` exists
  and says so loudly.
- **The audit** (`omega:loop --status`) walks every record, extracts named
  falsifiers, and resolves each to a test file carrying the id
  (word-boundary); unresolved ids are RED (LOOP_FALSIFIER_UNRESOLVED).
- **Bootstrap, stated honestly:** D-425's own stub was generated by this
  tool after its module landed, inside the same wave — the first
  generation bootstraps, as every constitution's first laws predate their
  enforcement machinery. Every record from here on gets its stubs at
  scaffold time; this record's own stub was generated and then implemented
  like any other (the tool exists by the time it runs — no special case,
  no exclusion).

## Consequences

- The development loop inverts to falsifier-first: scaffold → declare
  clauses → stub (RED) → implement → green → the gate carries it. A
  component is done when its falsifier passes — no interpretation gap
  between record and test.
- The named-falsifier convention becomes the load-bearing one for new
  records; the record-local F-N convention remains valid for the existing
  ledger and is deliberately out of the loop's scope.
- The audit adds a standing fact the round-close ceremony can consult;
  it is report-shaped at the CLI (the genome stage already enforces
  resolution for implemented layers — F-GENOME.3 — so the loop's audit is
  the tree-wide view, not a second enforcer).
- Zero host LOC; no new parsers; no write path outside tooling/gates/test/.
