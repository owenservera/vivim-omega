## 2 · The root-cause thesis — the program is not yet its own first customer

Every systematic friction found this round has **one root cause**: hand-maintained
derived state and hand-performed pre-analysis, in a program whose product
constitution *forbids exactly that*:

| The constitution says (atoms/records) | The program still does |
|---|---|
| MAC-05 — one `surfaceOpMeta` derivation, N surfaces in parity **by construction** | N hand-built process surfaces: index rows, README bundle table, handoff next-entry lines, round ledger rows |
| MAC-18 / CON-17 — no docs that can lie; badges print from data that cannot be hand-written | `BUILD-DECISIONS.md` status cells are hand-typed and regex-parsed — the five "bitten live" traps exist *because* derived data is hand-authored |
| The governed event — everything that happens is a ledgered row | Round-closure events (bundle cut, ratification) are prose in commit messages and README tables, not generated evidence rows |
| PHY-14 — the agent proposes, the compiler validates, the owner signs | Forks arrive at decisioning *unanalyzed*; the owner pays the analysis latency inline (the OD register names nine forks, none pre-analyzed) |
| MAC-18 auto-librarian — docs generated from tree + ledger | The read-first digest (`CURRENT-INVARIANTS.md`) regenerates on a *calendar cadence*, which is already stale by a full constitutional layer |

The corollary is the design principle for every accelerator below:

> **The forge forges itself first.** Each accelerator is the product's own
> constitutional claim, applied to the program that builds it — which means
> every accelerator doubles as an early, cheap proving ground for a product
> falsifier (MAC-18's generated docs get their first customer here; PHY-14's
> analyze→compile→sign shape gets rehearsed on our own decision records; the
> round-close ceremony becomes a governed event before Wave 4 has to invent
> them). Designing these now is not process indulgence — it is Wave-3/4
> product risk retired at tooling cost.

And the restraint principle, from the program's own S0 insight: **ceremony
kills experimentation** — so every accelerator must *remove* hand-actions per
round, never add them. Any design that adds a mandatory step without removing
a larger one is rejected in this review by rule (see §6, the restraint
register).

## 4 · Accelerator designs

Uniform card: root cause → design → landing → cost/leverage → the product
claim it rehearse. All land as tooling/docs rounds; zero host LOC.

### A1 · Record scaffold + generated index rows — kill the trap class at the root

**Root cause:** B4 (and the traps). `BUILD-DECISIONS.md` rows are hand-typed
derived data parsed by regex.

**Design:** `omega:new-decision <slug> --class evidence|directive` scaffolds a
record that passes the contract by construction (six sections in order, bare
status, `(a)/(b)/(c)` options matching the matrix, class tag emitted in the
index row). Index generation goes one step further than lint: the record gains
an `## Index` one-cell summary (or the checker derives it from the record's
title + class + status), and `omega:questions --write` regenerates *both* the
board **and** the index row for every D-360+ record — byte-stable for
unchanged records, append-only discipline preserved (rows below D-313
grandfathered verbatim, forever). The checker then gains one rule: *index row
must equal the generated row* — the trap class becomes unexpressible.

**Landing:** one tooling round, hygiene-class (`tooling/gates/decisions.ts` +
a scaffold script + tests). Ratified same-day on gate green per the B1–B4
evidence rule (no boot-security surface touched).

**Cost/leverage:** ~a day of tooling; removes the entire live-bitten trap
class and one hand-authored artifact per record, forever.

**Rehearsees:** MAC-18 (generated docs), MAC-05 (one derivation, N surfaces) —
the decisions index becomes the auto-librarian's first real customer.

### A2 · Round-close automator — the ceremony as one command

**Root cause:** B4. Six correct manual steps per round.

**Design:** `omega:round-close`: preflight (clean tree, quick green, decisions
contract green) → `git bundle create` per the existing protocol → sha256 →
append the README table row from the bundle + tip + tree hash (generated
from `git`, not typed) → regenerate board/status → print the next-round entry
block (the HANDOFF "next round's exact entry point" section, generated from
BACKLOG's top trigger + the open board). Refuses to run on a dirty tree or a
red gate — fail-closed like every other stage.

**Landing:** one tooling round, hygiene-class. Used for the first time at the
next bundle cut (`_4`).

**Cost/leverage:** small; converts the highest-error-prone manual sequence
into a checked operation; the bundle table stops being hand-maintained data.

**Rehearsees:** the governed event — round closure becomes a mechanical,
evidence-emitting operation rather than prose.

### A3 · Invariants digest on trigger, not calendar — close the B5 gap before Wave 1

**Root cause:** B5. The refresh policy (~30 ratifications) is slower than
wave-sized constitutional additions; it is already a full layer behind.

**Design:** CURRENT-INVARIANTS.md regenerates when any of: a wave closes; a
B-law or gate stage is added or amended; 30 ratifications accumulate —
*whichever comes first*. Enforcement starts report-only: a new gate stage
`invariants-freshness` computes staleness (last-refresh marker vs decisions
touching law/gate-stage rows since) and *reports*; after one green wave of
reports, it flips to failing (the D-368 → D-402 pattern: adopt, observe,
enforce). The digest itself is generated from the decision records (owner
amendments marked as such, as today) — not from memory.

**Landing:** one tooling/docs round; the first regeneration (pass #2) is the
round's deliverable — it must fold in Wave 0's forge constitution (anvil
freeze, generality axis, forge-surface, catalog freeze, the mine) and the
D-391 B5 re-freeze.

**Cost/leverage:** medium-small; fixes a *present* correctness gap (fresh
readers mis-state the law today) and becomes the MAC-18 harness.

**Rehearsees:** MAC-18 fully — staleness as a measured, named state.

### A4 · The `blocks` field — open decisions that block waves sort first

**Root cause:** B1. The board has no priority semantics; directive records
queue-jump blockers (D-407 displaced the partition decision — proven).

**Design:** records gain an optional `Blocks: Wave 1` / `Blocks: Wave 3` line
in Context (checker-validated vocabulary: wave ids + `none`); the generated
board gains a *Blocks* column and sorts blocking-first, then D-number. The
displacement class becomes visible at a glance: any wave whose blocker has no
record shows red on the board.

**Landing:** same tooling round as A1 (same file, same grammar).

**Cost/leverage:** tiny; makes the program's true serialization (owner
attention on blockers) visible in the program's own instrument.

**Rehearsees:** the consent-UX claim — the decision surface shows what is
awaited and why it matters, in priority order.

### A5 · Fork files — OD register entries pre-analyzed to lift-ready records

**Root cause:** B1/B3. Forks arrive at decisioning unanalyzed; the owner pays
analysis latency inline, in session time.

**Design:** each OD gets a working-set fork file in the repo's own six-section
record grammar (Status/Context/Options/Decision/Consequences/Evidence), with
an options matrix scored against named criteria, a recommended position, and
evidence citations. Decisioning then = *choose + lift* (the file becomes the
PROPOSED record nearly verbatim, next open D-id), not *analyze + author*.
Sub-forks that surface during analysis get named inline — the register stays
a register, never a blank page.

**Landing:** working-set only (this round delivers OD-1's fork file as the
first instance — see companion). Fork files for OD-2…OD-9 are authored as
their waves approach (OD-2/OD-3 before Wave 2; OD-5 with Wave 4 planning).

**Cost/leverage:** hours each, done outside session-critical time; each one
removes the analysis latency from the blocking path.

**Rehearsees:** PHY-14 verbatim — the agent analyzes, the record compiles,
the owner signs.

### A6 · Seam-wave reconciliation — the one program decision that changes the trajectory

**Root cause:** B2. The wave arc (falsifier-ordered) and the seam shortlist
(retrofit-cost-ordered) are two different orderings that have never been
reconciled on paper. Wave 1 as drawn (W5 atom + vertical slices) writes the
first conversation rows and chat surfaces — exactly the volume that makes S1
more expensive later (structural analysis: S1 is HARD, half-cut, on the
volume clock).

**Design:** the reconciliation matrix (§5 below) + a standing **seam ledger**:
for each seam (S1/S2/S3), the retrofit-cost driver, the wave that starts the
clock, and the cut-by wave. The ledger lives in the working set now and in
the annex at re-entry; each wave's scope decision checks it explicitly.

**Landing:** this document is the design; the decision is the owner's (it is
Wave-1 scope). No tooling.

**Cost/leverage:** zero cost, highest single leverage in this review.

### A7 · Cross-track decision registry — IDs that cannot collide

**Root cause:** B6 (D-389 proven).

**Design:** a naming law, not a tool: external tracks cite decisions
track-qualified (`omega:D-389`, `akb:D-389`); the working set carries the
reconciliation table (begun in the integration doc §3); the authoring lint
(A1) warns on bare `D-NNN` citations that resolve to a different track's
ledger. Registry file: one page, working set now, annex at re-entry.

**Landing:** convention lands with A1's round; the table already exists.

**Cost/leverage:** trivial; prevents a whole confusion class permanently.

### A8 · Citation verifier — evidence claims that check themselves

**Root cause:** B7. D-408 needed a full hand re-verification pass.

**Design:** `omega:verify-citations`: extract quoted strings + `file:line`
refs from decision records; verify each against `reference/` (the corpus is
pinned — fixture hashes + the bundle protocol); report drift as named rows.
Runs as a report-only gate stage for one wave, then advisory-failing for
records authored after its adoption (retroactive enforcement deliberately
excluded — the grandfathering pattern).

**Landing:** tooling round after A1/A2; needs the corpus pin check to exist
(hash manifest over `reference/`, or an explicit out-of-band pin declaration
with its limits named).

**Cost/leverage:** medium; converts the most expensive hand-verification pass
(re-verification rounds) into a command.

**Rehearsees:** CON-16 — "why" is a query, not an archaeology project.

### A9 · Gate tiering (changed-since DAG) — design insurance, deliberately deferred

**Root cause:** B8 — *recalibrated to low*. 64s at 4-wide; two greens are
minutes.

**Design (kept on paper only):** shard the full gate by the existing lanes
(`omega:test:host/plugins/surfaces` already exist); each shard records
{input-tree hash, concurrency, result}; a composite green = all shards green
on identical inputs, replayed by hash. **The ratification bar is unchanged**
— full gate on the ratify tree, twice, on Linux; tiering only accelerates the
dev loop and CI. Amends gate semantics, so it requires its own evidence-class
record with an adversarial test (a tampered input under a replayed hash must
fail).

**Landing:** not before test count ×5 (Wave 4-ish). This review's choice: do
not build it now; the 64s measurement is the evidence.

**Rehearsees:** the governor — dormant/hydrated test suites are the Tile
State model applied to the program's own biggest workload.

### A10 · Mine-operations harness — performance budget from the first receipt

**Root cause:** B9. The synthetic mine is 42 files; the real mine is ~100×.

**Design (sketch, lands with Wave 1):** capture/verify/diff drivers with
incremental hashing (content-hash cache keyed by path+mtime+size), snapshot
cache (CAS blobs, one write per unique content), and a stated perf budget in
the D-record that lands `forge-mine` (e.g. capture of the synthetic mine <
N seconds on the CI lane; the real-mine first capture gets its own measured
baseline before any optimization is permitted — measure, then cut).

**Landing:** Wave 1's tooling, inside the forge-mine round.

**Rehearsees:** resource profiles (PHY-02) — the mine ops declare a budget
like any composition.

### A11 · Working-set landing path — the annex

**Root cause:** B10. Seven external files, one restore path.

**Design:** at re-entry, the working set lands in the repo as
`docs/forge/annex/` with a two-line status discipline (annex files are
working material — versioned, citable, never law; the vision itself still
lands per PARKED-STATE's restore path). The atoms, structural analysis,
integration companion, OD register, fork files, and this review all get homes;
future working material (fork files for OD-2+) is authored *in* the annex from
then on — no more out-of-repo divergence.

**Landing:** part of the re-entry round (directive-class, docs-only).

**Cost/leverage:** trivial; ends the two-worlds problem permanently.

### A12 · Toolchain pin in evidence — one line

**Design:** the gate's status output records bun/node/OS versions next to the
concurrency cap it already records; `verify-status` compares them.
**Landing:** rides along with A2's round. **Rehearsees:** evidence
reproducibility (D-362) extended one notch.

## 7 · Falsifiers of this review

In the house style — each design here should be killable by evidence:

- **If Wave 1 lands without S1 and the W5 retrofit later proves cheap**, A6's
  urgency was overstated: the seam ledger demotes, and the structural
  analysis's volume-clock grade for S1 softens.
- **If five rounds pass with zero checker-trap reds after A1 lands**, the trap
  class was already dying on its own: A1 was insurance, not acceleration.
- **If CURRENT-INVARIANTS regenerates within policy without the trigger
  stage**, A3's enforcement was unnecessary — the calendar was enough.
- **If no further queue-jump displacement occurs for 10 decisions**, A4 was
  solving a one-off, not a class.
- **If the full gate stays under ~3 minutes through Wave 4**, A9 stays dead —
  correctly.
- **If round-close automation (A2) ever masks a red gate or a dirty tree**,
  it violated fail-closed and must be reverted the same day — the design's
  own first falsifier.
