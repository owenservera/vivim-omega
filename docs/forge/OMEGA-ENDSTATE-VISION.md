## 2 · The Natural Language Control Plane

> **Probabilistic perception. Deterministic intent. Deterministic execution.**

Vivim is conversational at the edge and deterministic at the core. A person should be able to operate it in language that feels almost like talking to an LLM — *"find the invoices from last month, group them by customer, and put the overdue ones in my Finance workspace"* — while the machinery beneath is not an LLM, and the trusted execution path never requires one. This is not "chat over an application." It is **natural language operating the environment itself**, and it is a constitutional peer of local-first, provenance, and refusal-first — not an NLP subsystem, not an implementation cleanup.

The corpus already knew this, and measured it. The vivim-next MASTER-SPEC's first two defining properties are *hot-swappable intelligence* — "NLP, NLCL, and LLM escalation are deterministic, composable tiers — not monolithic magic" — and *natural language reprogrammability* — "every visible and controllable surface obeys a closed mutation grammar." The MASTER-BLUEPRINT's intent-signal table puts `capability-system` at **377 signals — the single highest topic in the entire mine** (above `providers` 241, `ui-ux` 202, `conversation` 174, `agent-execution` 103, out of 3,225 mined intent statements). The subsystem this document once filed under a one-line FRESH verdict (§28, row 4) is the corpus's most-invested idea. This section restores it to the tier the corpus gave it.

```
Human language
      ↓
Perception / semantic interpretation
(rules · lexicon · grammar · classifiers · ML where useful)
      ↓
Canonical Intent          ← typed, inspectable, reproducible
      ↓
Capability resolution     ← against the capability graph
      ↓
Law / consent / refusal   ← the gate consumes canonical intent, never model output
      ↓
Deterministic operation plan
      ↓
Deterministic execution
      ↓
Evidence / provenance / event
```

The ML layer is allowed to be uncertain. **The execution layer is not.** The single structural guarantee that makes this constitutional:

> **No raw model output crosses the law gate. The law consumes canonical intent only.**

An LLM may participate as a *replaceable intelligence realization* where generative or reasoning intelligence is genuinely needed — interpreting the ambiguous tail of language, synthesis, generation, external model interaction — substitutable, revocable, stamping `realizationRef` on every row it produces, exactly like every other realization in the stack. It is never the constitutional authority that decides what Vivim did. Remove every model and the system still resolves, gates, and executes; it loses synthesis, not control.

**The deterministic promise:** the same intent, against the same state, capabilities, and policy, resolves to the same executable meaning. Where certainty is insufficient, Vivim does not guess silently — it asks, narrows, or refuses:

```
UNDERSTOOD   "Open my GitHub PRs."
AMBIGUOUS    "I found two GitHub accounts. Which one?"
REFUSED      "This would delete 43 files. I need your approval."
EXECUTED     "Opened 12 PRs in the current workspace."
```

Which yields the layer table — deterministic where it must be, optional where it is allowed:

| Layer | Nature |
|---|---|
| Understanding language | deterministic tooling + ML |
| Canonical intent · capability resolution · permissions | deterministic |
| State changes · evidence · provenance | deterministic |
| Reasoning · synthesis · generation | **optional** ML/LLM |
| External AI providers | replaceable realizations |

**LLMs are optional intelligence providers. Natural language is not.** Vivim does not need a frontier model running to resolve *"open my inbox"* or *"put this beside my project notes"* or *"show everything Owen created this week"* — those resolve through local deterministic language machinery into canonical operations. An LLM becomes necessary only when the *task itself* requires generative intelligence (*"read these 40 emails and tell me which customers are at risk"*). That is the difference between a clever orchestration layer around other people's AI and what Vivim actually is: **the system owns the intelligence environment; models are replaceable engines inside it** (§12). The sharpest form of the whole claim: *Vivim gives you the feeling of talking to an intelligent computer without requiring the computer to surrender control of itself to an unpredictable model.* Probabilistic cognition at the boundary; deterministic semantics at the center.

And because language, canvas, CLI, MCP, automation, and agent all converge on the same canonical intent and operation vocabulary (§11), there are not multiple ways to *implement* an operation. There are **multiple ways of expressing the same operation** — all governed identically, all producing the same event shape. That is the point at which Vivim stops being an application with an AI interface and becomes a **natural-language operating environment** — and the mechanism that makes the one-sentence vision's final clause, *"buildable by anyone who can describe what they want,"* something better than a wish.

*Falsifier owed (F7, Wave 3 — §30): the same natural-language intent, issued twice against identical state/capabilities/policy, produces byte-identical canonical intents and identical operation plans; a below-threshold confidence produces a named clarifying question or refusal, never a silent guess; and no LLM token appears in law-gate input or anywhere in the execution path.*

## 5 · The atom — the governed event

Strip every layer away and one thing remains, because removing it removes the product itself:

> **A governed event: something happened — was requested, observed, produced, changed, approved, refused, or inferred — by a principal, through a capability, under a law, with provenance and retention.**

A conversation turn is the *first important specialization* of that atom — *"this turn happened, through this realization, gated by this law, vouched for by this principal, with this retention, citing this evidence"* — and it is the W5 falsifier's exit gate. But the environment is not made of conversations. It is made of governed events: a file changed, an email observed, a login proven, a healing approved, an automation fired, a query answered, a tile forged, a capability delegated, a treaty signed, a refusal issued. An AI/conversation platform has one kind of atom; an operating environment has one *shape* of atom and many *kinds* — and the shape is what the constitution protects. Collapsing the atom back to the conversation turn would quietly collapse the product back into "a sophisticated AI conversation system," and everything else in this document says it is larger than that.

Everything else orbits the governed event: surfaces **present** it; providers **produce** it; engines **shape** it; automation **sequences** it; memory **accumulates** it; the capability graph **attributes** it; the intent layer **expresses** it; the law **gates** it; provenance **stamps** it. The W5 falsifier states the first mile as one bite — *a person types, a real streamed response comes back through the law gate, ledgered and queryable* — a conversation event, because conversation is where the spine proves itself first, not because conversation is what the system is.

Three contract shapes hold from the first row (cheap now, a migration each later):

1. **Refusals are sentences.** Every refusal payload carries `{ code, sentence }` — the system says no *out loud, in a sentence a human understands*, rendered as an ordinary boring event. A stack trace is a bug; a sentence is a product.
2. **Ledger rows answer "why."** Every row cites evidence (refs with byte offsets) and a reason. "Why does this work this way?" is a *query*, not an archaeology project.
3. **Both badges on every row, from row one.** `ProvenanceTier` (who vouches) × `generality` (what it has been proven against) are stored together on every realization/artifact row from the first write. Pixels come later; data that never existed without its badges cannot retroactively grow them.

## 6 · The live object — the 5-tuple, and the four choicepoints resolved

The atom of the *spatial* half is the live object (the tile). It is a **5-tuple**, nothing more:

| Field | Meaning | Lives in |
|---|---|---|
| **identity** | stable across sessions, devices, and upgrades | the object model |
| **composition** | the running, signed, capability-scoped thing | `compositions/` |
| **vault binding** | where its state is, who writes it, retention | `ns <domain>` |
| **spatial placement** | position, size, z-order, zoom — versioned, restorable, synced | `ns canvas` |
| **provenance badge** | who vouches · what it is proven against | both axes, on the row |

A tile is *live* because a real composition runs underneath it — a real logged-in Gmail session in a Chrome instance the user never sees — streaming rows into the vault, and the tile re-renders when the vault changes. **The tile never polls. It observes.** *Live* is a defined property, not a marketing one (§9); staying live inside a physical budget is the governor's jurisdiction (§18); and the rectangle is one projection shape — the object kinds a tile may project are §9's. The four open choicepoints from the end-state design are resolved here (directive D-407; each resolution owes its falsifier to the wave that builds it):

### CP-1 · The object-model substrate

**Decision: the vault watch is the substrate. CRDT is a merge discipline folded over the log — never a second source of truth.**
The authoritative object graph is a fold over the append-only vault log (event-sourced). Multi-device sync syncs *vault facts*, never derived state. Inside `ns canvas`, placement updates carry CRDT semantics (per-object last-writer-wins registers; commutative placement ops), so concurrent edits from two devices merge deterministically when logs reconcile. Yjs/Automerge-style engines may appear as *payload shapes inside namespace rows*; the ledger itself stays one vault, sole writer per namespace, append-only, retention-named. **Why not CRDT-as-substrate:** it would put a second truth beside the vault, and Ω's constitution has exactly one.
*Falsifier owed (canvas wave): two devices diverge → logs reconcile → both converge to identical layout, zero lost non-spatial rows, one named merge record in the ledger.*

### CP-2 · Where tiles execute

**Decision: trust-tiered execution — first-party at `worker-thread`; every user-forged tile at `process` (ndjson via `vivim.run`) under watchdog budget and capability grants; `wasm` is the sealed endgame tier, forward-declared until a real tile earns it.**
Nothing user-forged ever shares the primary runtime. The anvil never grows a line for tile execution — the process tier already exists (D-374) and the supervisor already restarts-or-stops-loud (D-397). Sandboxing is not a feature we add; it is a refusal we inherited.
*Falsifier owed (tile wave): a forged tile that infinite-loops is killed by the watchdog with zero host LOC and a named refusal; a forged tile touching an ungranted capability is refused — with a sentence.*

### CP-3 · Spatial state ownership

**Decision: `ns canvas` is first-class vault data. Sole writer: the canvas surface plugin. Retention: versioned, restorable snapshots. Rows reference object identity — they never duplicate object state.**
This is what makes layout *forge-able*: diffable, replayable, healable like any other row, and "remembers exactly where you left everything, across devices" falls out of the vault being append-only and synced — it is not a sync feature, it is a consequence.
*Falsifier owed: delete the canvas app → reinstall → layout restored exactly from the vault; a layout write from any writer but the canvas surface is a named refusal.*

### CP-4 · The first forgeable tile

**Decision: a local, provider-free, vault-backed tile first — the Ω Ledger Lens** ("show me what happened, live": a live query over the vault as a tile). It exercises the full 5-tuple, vault-watch liveness, the law gate, the badge lifecycle (`speculative` → `harvested`), and the consent surface with **zero external rot**. The healing-loop provider tile (Gmail-style) is deliberately *second*: prove the substrate before the storm. A canvas that cannot survive without a browser fleet has no substrate at all.
*Falsifier owed: a non-programmer forges the Lens from one sentence, consents in one tap, sees live data with both badges; kill the canvas and the CLI answers the same query.*

To a person, Vivim is not an app they open. ## 12 · The intelligence model — the fabric, and the engines

For a product whose founding sentence once read *"my machine, my data, my AI,"* the AI layer must be explicit, or the product reads as "a clever orchestration layer around other AI providers." It is not. **Vivim owns the intelligence environment; models are replaceable engines inside it.** The intelligence fabric is kernel-side machinery that decides — deterministically, from ledger rows — *which model, which context, which memory, which tools, which capabilities, which evidence, which privacy level, which latency, which local/remote policy, which cost* for any given task. The fabric's decisions are themselves governed events: queryable, replayable, refusable.

The fabric's hardest job is the **context window — the mind spine**. The vault is append-only and infinite; the context window is finite; therefore context is a *first-class resource*, assembled rather than assumed:

```
VAULT (append-only · retained · epistemically typed — §13)
      ↓  semantic router (deterministic, queryable projection of the vault)
RETRIEVAL over namespaces (localized RAG · evidence refs with byte offsets)
      ↓  retention + eviction rules (named, per namespace)
ASSEMBLED CONTEXT WINDOW        ← metered like any resource (§18)
      ↓
REALIZATION (local or remote · substitutable · realizationRef on every row)
```

The mind spine is a **deterministic, queryable projection of the vault** — not a vibe and not an opaque cache: the same query against the same vault assembles the same window (the F12 falsifier), every included memory carries its evidence refs and its epistemic kind (§13), and eviction is a named rule, never a silent truncation. The corpus had the machinery's name on its books all along — a first-party `ContextAssemblyEngine` sits in the old inventory — and the Ω version is that engine rebuilt as law-gated, evidence-citing vault machinery.

## 13 · The memory model — why Vivim remembers

"Memory belongs to its owner" is the *storage* property. The user-facing property is *epistemic*: Vivim can say **why it remembers something, and on what basis the memory may be cited.** Every remembered row declares both a human-facing semantic type — *remembered, temporary, project memory, personal memory, derived knowledge, source material, working context, private, shareable, expiring* — and an epistemic kind:

```
FACT · SOURCE · OBSERVATION · INFERENCE · OPINION · SUMMARY ·
MODEL-GENERATED BELIEF · USER ASSERTION
```

The retention rule solves the storage problem; the epistemic kind solves the knowledge problem. Source material is pinned and re-fetchable; observations carry their evidence refs; inferences carry their derivations; model-generated beliefs are *labeled as such* and never silently promoted to facts — they are badges (§27) turned inward, the same honesty axis applied to memory itself. A memory that cannot name its kind is a rumor, and the vault refuses rumors the way it refuses unlabelled generality (§29). "Why do you think that?" gets the same class of answer as "why does this work this way?": a row.

## 14 · The agency model — who may do what, for whom, for how long

```
Human ──delegates──▶ Agent ──uses──▶ Composition ──invokes──▶ Plugin
                                    └─accesses──▶ Capability ──operates on──▶ Resource
```

Every edge in that chain is a ledger row carrying **principal, capability, scope, duration, approval mode, revocation, and evidence.** This is what makes sovereignty an *agency* property and not merely a data property — the difference between a system that owns your data safely and a system you can safely put to work. The right to refuse (§5) is half the constitution; the other half is the **right to delegate deterministically**. Consent without delegation is bureaucracy: a consent the user cannot zone becomes a consent the user taps blindly, and a blindly-tapped consent is a security failure wearing UX clothing.

Therefore: **trusted radii.** The user may grant "auto-approve healings for `provider.gmail` when the proof report passes," or "auto-forge tiles in `ns sandbox`" — and every radius is itself a governed object: named, scoped, expiring, revocable, on the ledger, inspectable with the same INSPECT verb as everything else. Escalation is the mirror of delegation: when a request exceeds a radius, the system does not guess and does not nag — it surfaces one consent request with the principal, the scope, and the reason, in a sentence. Sovereignty includes the right to say yes *once*, precisely, and have it hold.

## 15 · The temporal model — time as a first-class dimension

Event sourcing gives the environment a capability most products fake: **real time travel.** The canvas is a function of the log up to time *T*, so "show me what my world looked like last Tuesday" is a projection, not a feature build. The user-facing temporal verbs:

- **Scrub** — drag the canvas back through a temporal scrubber; every object renders its state at *T*; the ledger row under it says why.
- **Undo** — fifty tiles accidentally deleted is a scrub, a tap, and a branch; zero permanent loss.
- **Rewind without erasure** — append-only is constitutional (§5), so rewinding never deletes history; it **forks a branch** the user may merge back or discard. The ledger shows the deletion, the scrub, and the branch — honesty preserved *through* the mistake, not despite it.
- **Scope-undo** — "undo everything this agent did in the last hour" is compensation events filtered by principal + window; agency (§14) and time compose.
- **Replay** — re-run a workflow against the state of September 12; the vault still has it, byte-addressed.

The same substrate carries **agentic time**: long-running, headless compositions — Eve's legacy-app forge run that takes hours (§24, Evening) — live as **sleeping compositions**: event-driven or time-triggered, waking on vault events or timers, running to completion and ledgering as they go, completely independent of any canvas projection. When X happens, do Y — *new GitHub PR with label `investor` → summarize → create research tile → notify → remember* — is a first-class composition, not a script bolted onto the side. The temporal plane belongs to the kernel, not to the pixels (F1).

## 16 · The sharing model — the machine, never the data

The old tagline had three clauses — *own your AI, share your AI, evolve your AI* — and this vision owed the middle clause its architecture. The principle:

> **You share the machine, not the data.**

```
Alice's Gmail tile
   ↓  export composition
capability requirements (unbound — "needs a Gmail read capability")
   ↓  strip credentials · strip private state · retain provenance
Bob installs · grants HIS OWN capability · the tile runs on Bob's data
```

An exported composition carries its structure, its provenance, and its *needs* — never Alice's secrets, never Alice's state. Forking is a branch with a fresh generality badge (`speculative`, earned anew by its new owner's proof); publishing is Forge distribution; installing is consent plus capability grant — all the same doors as Part I, because there is only one door.

**Two sovereigns, one canvas.** When Alice and Bob co-author, there is no shared server and no merged identity: spatial state merges by CRDT fold (CP-1); object state crosses the boundary only through **explicit capability delegation under a temporary, mutually-signed treaty** — scoped, expiring, revocable, mirrored on both ledgers. A shared canvas is not one composition; it is **the intersection of two sovereign compositions, gated by a treaty.**

**Discovery without a store.** No cloud account means no central app store: Forges publish manifests and content hashes to decentralized indexes (transparency-log style), and trust travels by **petnames and curators** — the badge grows a vouch line: `third-party · vouched by @alice-curates`. A Forge with a valid signature but drifted code is rejected by the content-hash gate; a Forge nobody vouched for is installable but says so, plainly. The marketplace is a web of sovereigns, not a mall.

## 17 · The sovereignty test — the right to leave

The strongest sovereignty test is not "who holds the keys" but **"can the owner leave?"** A local-first walled garden is still a walled garden. Therefore, as constitutional direction:

- **The Exit Manifest** — a full vault export in a documented, open format: the CAS blobs, the event log, the compositions, the canvas spatial state, the provenance. A fresh Ω node — or a third-party viewer — must be able to ingest it and reconstruct the user's environment byte-identically, minus execution capabilities (F10).
- **Machine migration, encrypted backup, restore, schema migration** — the lifecycle verbs (§22) under the same openness guarantee: no essential user state exists in a format the user cannot export.
- **Portable compositions, portable provenance** — a shared tile (§16) carries everything but secrets; an exported vault carries everything, period.

Sovereignty, fully stated at last: the user owns the memory (vault), the law (consent), the agency (delegation), the time (branches), the machine (budgets), the sharing (treaties) — *and the exit*. A constitution without a door out is a cage with better lighting.

## 18 · The resource constitution — the thermodynamics of the canvas

Sovereignty has a physical cost: fifteen hidden Chrome instances, a local model holding 4 GB, a live vault, and a canvas will melt a laptop — and a product that melts the laptop gets uninstalled, no matter how honest its badges. **The machine is sovereign territory too.** CPU, RAM, GPU, disk, browser sessions, network bandwidth, model memory, and battery are all *governed resources*, and the kernel is their OS-level scheduler — not just their capability router.

- **Resource profiles.** Every composition declares one (a Gmail tile: ~200 MB, network-poll 5m; a local-LLM tile: 4 GB, GPU). A forge proposal without a profile is refused — with a sentence.
- **Tile lifecycle.** Objects move through visible states: **ghost** (layout + identity + vault watch only; heavy realization shed), **dormant** (light realization, paused), **hydrated** (full realization), **suspended** (governor-forced). Spatial placement dictates allocation: off-viewport or idle for *N* hours → shed the realization, keep the ghost watching the vault. **A thousand objects can exist in a workspace without requiring a thousand active runtimes.**
- **The budget watchdog.** Physical events are law: laptop unplugged → suspend the Chrome fleet within seconds, keep the vault, the ledger, and the Lens alive; no OOM kills, no silent death. Degradation is *never* invisible — it is a badge state (§21), because a quiet freeze is a lie of omission. The badge says: *"Suspended to save battery. Tap to wake."*
- **The context window is metered here too** (§12): the mind spine's assembly is a first-class scheduled workload, not a free river through the model.

*Falsifier owed (F8, Wave 4 — §30): 20 live tiles running; the user unplugs the laptop; the scheduler deterministically suspends the heavy tiles within 2 seconds; the system remains responsive; zero OOM kills.*

## 19 · The identity constitution — keys that survive the hardware

The constitution signs every row (§5), so the *keys* are load-bearing, and the vision owed them an explicit model. The principals: **human, local device, first-party forge, third-party forge, plugin, agent, provider, organization, signing key.** The questions the identity layer must answer constitutionally:

- **Pairing.** No cloud account means Device A must learn to trust Device B locally: PAKE-based local-network pairing, hardware security keys, QR rituals — a **local trust mesh**, never a server.
- **Survival.** A lost laptop must not be a lost vault: recovery via socially-distributed key shares (Shamir-style secret sharing across trusted devices and people), encrypted exports (§17), and rotation that re-keys without rewriting history — a signature row cites the key that made it, and rotation adds a row; it never edits one.
- **Authority.** What invalidates a signature (revocation rows, tier demotions) is named; why provenance cannot be forged (the badge prints from ledger rows a non-writer cannot write — namespace sole-writers are the anti-forgery); and why an untrusted plugin cannot impersonate a first-party one (**ProvenanceTier is assigned by the kernel, never claimed by the artifact** — the same discipline the generality axis already enforces).
- **ACLs.** The sole-writer rule per namespace implies access control lists managed entirely by local cryptography — the vault's locks are the keys, not a service.

*Falsifier owed (with the first multi-device wave, CP-1's): two devices pair locally with zero network authority; a key rotates; old rows still verify; the revoked key's next write is a named refusal.*

## 20 · The security constitution — the threat model, stated

Sandboxing, watchdogs, and refusal are the machinery; the *threat model* is the constitution's adversary clause, and it is written down, not ambient: a malicious plugin, a compromised provider, a poisoned Forge, a malicious composition update, credential exfiltration, prompt injection, hostile web content, a malicious imported artifact, a supply-chain dependency, forged provenance. The crown property — the one this product alone can print:

> **Untrusted data can inform a composition without gaining authority over the composition.**

Gmail's redesigned DOM, a fetched email's injected instructions, a model's confident hallucination — all of it may *inform*; none of it may *authorize*. The mechanism is the **intent airgap** (§2): the perception layer — LLM or otherwise — proposes a natural-language draft and a JSON schema; a deterministic compiler validates it against the `pack.builder` schemas; the consent surface shows the *compiled, validated plan* in plain words; and the user signs that, never the model's output. **The LLM proposes; the compiler validates; the user signs.** An adversarial prompt injection can, at worst, produce a refused draft — a named refusal before the consent surface is ever reached. Browser sessions are quarantined realizations (CP-2); supply chains are content-hash and curator gated (§16); nothing promotes unreviewed (§29). The security model is not a layer in the stack — it is the stack's refusal to have an unsupervised layer at all.

## 21 · The failure vocabulary — every failure is a state, every state is recoverable

Refusal is how the system says no to a *request*. Failure is how it says no to a *situation* — and both must speak in sentences the user can act on. The user-facing vocabulary, each a named state on the object, each a ledger row:

```
Paused · Degraded · Broken · Quarantined · Stale ·
Untrusted · Revoked · Repair available · Rollback available
```

Each maps to machinery that exists or is owed: *Refused* → the law gate (§5); *Degraded* → handler fault, fail-closed; *Stale* → drift detected against the canonical shape, healing loop pending (§26); *Quarantined / Untrusted / Revoked* → trust-tier and key states (§19, §20); *Repair available* → a healing proposal awaiting ratification; *Rollback available* → a replay point exists (§15). The constitutional promise: **every failure leaves the user with a recoverable state** — because the vault is append-only, the evidence is cited, and the branches exist. A crash is a bug; an unrecoverable crash is a constitutional violation.

        ↓

## 26 · The healing loop — the Forge turned outward

The deepest identity in this architecture: **provider self-healing and application forging are the same pipeline at two scales.** There is no second "healing engine" to build, and that is a *feature* — if the pipeline can heal a redesigned login page, it was never Vivim-shaped.

```
LOCAL CANONICAL PROVIDER   (roles · structure · states · transitions — never selectors)
        ↓
BEHAVIORAL CONTRACT        (capabilities · invariants · oracles)
        ↓
OBSERVATION ENGINE         (DOM · AX · NET · WS · runtime · events)
        ↓
DRIFT ENGINE               (structural · semantic · behavioral · protocol diff)
        ↓
REPAIR ENGINE              (correspondence · remapping · parser/protocol migration)
        ↓
VALIDATION ENGINE          (replay · contract tests · state machine · counterexamples)
        ↓
RATIFIER                   (vN → vN+1 · provenance · rollback · a human signs)
```

| Healing stage | The Forge op it already is |
|---|---|
| observe | `forge.mine.capture@1` / `forge.mine.verify@1` |
| detect | `forge.mine.diff@1` |
| discover / propose | `forge.survey.run@1` / `forge.shape.map@1` / `forge.emit.*@1` |
| prove | `forge.proof.conform@1` / `forge.proof.refusal@1` |
| ratify | `forge.tier.promote@1` (Class-4 Govern — never grantable to a non-root principal) |

Selectors — the rotting truth of v1 — become **derived, disposable projections of a shape**. The stored unit is the canonical shape; the selector is regenerated the way a CLI command is regenerated from `surfaceOpMeta`. The healing loop is also the ultimate generality test for the Forges themselves: the synthetic mine breaks them today; a healed Gmail breaks them tomorrow; what survives both was generic all along.

## 29 · The refusal register — what the dream itself refuses

The ideal product is defined as much by what it refuses as what it does — and every refusal below is enforced by a gate, a label, or a law row, not by intention:

- **No cloud account, ever required.** Local-first is a boot property, not a settings toggle.
- **No telemetry, no attention metrics.** Nothing measures the user's gaze; the ledger records *system* events, not human attention.
- **No silent promotion.** Nothing auto-heals, auto-updates, or auto-publishes into production unreviewed; the quietness is UX, the authority is never quiet.
- **No SDK above Ω.** Forges are ordinary plugins; the tooling that builds the tooling passes the same doors.
- **No selectors as stored truth.** Canonical shapes are the unit; selectors are disposable projections.
- **No docs that can lie.** Provenance and generality print from data; a claim without evidence is `speculative` and says so.
- **No unlabelled generality.** Harvested is not a failure state; an *unlabelled* one is — and it is a hard gate error.
- **No privileged path.** Not for first-party, not for the Forge, not for us.
- **No namespace without a retention rule.** If we cannot say what it forgets, we refuse the namespace.

*Added by D-408 — the civilization and physics refusals:*

- **No raw model output crosses the law gate.** The law consumes canonical intent only; a model is a realization, never the resolver of record.
- **No silent intent resolution.** Below-threshold confidence asks, narrows, or refuses — out loud, in a sentence. A silent guess is a bug.
- **No LLM in the trusted execution path.** Remove every model and the system still resolves, gates, and executes; it loses synthesis, not control.
- **No authority from data.** Untrusted data may inform a composition; it may never gain authority over it.
- **No resource without a budget.** Everything live is metered; degradation is a visible state, never a quiet freeze.
- **No consent that cannot be zoned.** Sovereignty includes the right to delegate trust deterministically — radii are named, scoped, expiring, revocable rows.
- **No sharing without a treaty — and never the data.** Capability crossings between sovereigns are mutually signed, scoped, and expiring; exports carry the machine, never the secrets.
- **No remembered row without a named kind.** A memory that cannot say whether it is fact, source, observation, or belief is a rumor; the vault refuses rumors.
- **No lost device loses the vault.** Key survival is constitutional: pairing without servers, recovery without custodians of last resort.
- **No essential state the user cannot export.** Local-first is honest only if the door out is real (§17).
