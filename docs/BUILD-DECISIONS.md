# Ω Build Decisions (D-2xx build track)

Append-only register for the fresh-tree build. Phrasings mirror the program repo's D-register
conventions (PROPOSED → RATIFIED; supersede, never edit).

| ID | Decision | Status | Rationale |
|---|---|---|---|
| **D-210** | Adopt VIVIM-Ω (D2) as the architecture of record and **build the core fresh**: a standalone tree (`vivim/vivim-omega`), not shaped by, strangling, or harvesting the legacy vivim code during the build. Legacy backfill happens **after** the core exists ("we will later backend into the new core"). | **RATIFIED** (owner directive, verbatim: *"I want you to first fully build the new core system with everything you outlined in vivim omega - we should not shape the perfect end state with the old vivim code - we will later backend into the new core"*) | Supersedes D3's D-201 (build inside vivim-final-enhanced) and defers D-204 (harvest-during-build) to the backfill phase. The old repos are frozen mines, untouched (fresh-tree guard gate). |
| **D-211** | Zero-runtime-dependency core: compartments via `node:worker_threads`, storage via `bun:sqlite` (WAL+FTS5, probed green), signatures via `node:crypto` ed25519, hashes sha256. The @noble pin (D-206) is amended to node:crypto — same algorithm class, no dependency. | RATIFIED (verified in-sandbox 2026-09) | Available today, boring, honest. Algorithm fields remain pinned in the Recipe (`hashAlgo`) so upgrades are declared changes. |
| **D-212** | Waves Ω0–Ω9 per D3 `03-WAVE-SPECS`, each ending in a **booted composition** with green gates (`bun run omega:gate`), benchmarks in `BENCHMARKS.md`, and status in `build/status.json`. Tests are gate evidence (TEST is contribution kind #9) — the sandbox no-test rule applies to the Next.js review console, not to the Ω product itself. | RATIFIED (owner authorized the build of "everything you outlined") | D-205's existence-proof law, carried into the fresh tree. |
| **D-213** | Ω0 composition includes a `law-stub` plugin occupying the `vivim.law` slot (id `vivim.law`, allow-all policy) so the boot-order law is real from wave 0. Ω1 replaces it via a recipe re-compile + atomic pin swap — the first live demonstration of the amendment protocol. | PROPOSED | Keeps the µhost honest (phase 0 = vivim.law is enforced, not special-cased) without requiring the full law plugin in wave 0. |
| **D-214** | Anti-loss: local commits per task on branch `omega`, wave tags `omega/w0`…, `git bundle` + tarball mirrored to the sandbox `download/` area via the console's `/api/download` route. No pushes (sandbox has no credentials — §4.7 law). | RATIFIED (standing law) | D-208 generalized to the fresh tree. |
| **D-215** | Self-knowledge is a PLUGIN (`vivim.mind`, Ω10), not µhost code. The µhost stays untouched (≤1,000 LOC law). The mind derives the WorldModel from law.registry + vault + composition-config projections; it writes nothing, so a wrong self-model is falsifiable against intact evidence. | RATIFIED (owner: "if there are any core primitives needed in the core ensure you properly segment - if pure plugins is best that's ok") | Pure plugins is best: every concern in the directive (self-knowledge, NLP, reprogramming, feedback) is a swappable plugin; the core stays boring. |
| **D-216** | NCLL (Natural Command Language Layer) is an upgradable ENGINE plugin (`vivim.nlcl`, Ω11) wrapping a dependency-free pure package (`plugins/vivim-nlcl/pure` published as `@vivim/omega-nlcl-pure`, zero imports). Determinism law N1: same (text, WorldModel, version) ⇒ same interpretation — in compartment, surface server, and browser. The LLM is never in the parse path (edge-only, opt-in, marked probabilistic — law N2). | RATIFIED (owner: "the deterministic NLP and nclc as a core upgradable plugin") | One signed unit to hot-swap the whole language engine (recipe re-compile + atomic pin swap); same bytes for keystroke-latency browser feedback and authoritative server parse. |
| **D-217** | Symbol families: 17 core-primitive command families (`/ @ # ! ? + - & $ * % ∆ ✓ = ^ ~ →`) are LEXER primitives (code); their NL expansions are lexicon data. Canonical symbolic forms are first-class IR output shown beside every NL parse (gap-narrowing feedback). | RATIFIED (owner directive, verbatim symbol list) | Families are grammar (stable), meanings are data (upgradable/teachable). |
| **D-218** | Language frames (verbs/slots/prepositions per op) live as data in nlcl-pure keyed by op id; taught words live in vault ns `nlcl` (survive plugin swaps). Post-v1 path: a `lang` contribution kind owned by packs — a contract-grammar change = amendment-class event, deferred. | RATIFIED (design recommendation) | Keeps v1 contract surface frozen; upgrades stay atomic; the amendment path is documented, not improvised. |
| **D-219** | Reprogrammability (Ω12 `vivim.director`) is DATA ONLY: rules (vault ns `automation`), teachings (ns `nlcl`), consents (law ops). A deterministic 500 ms tick loop matches vault state against rules and executes actions through the port under principal `vivim.director` — the law still gates rule actions (one consent at rule-creation). No code is generated, ever. | RATIFIED (owner: "BACKEND IS FULLY REPROGRAMMABLE BY NON TECHNICAL USERS USING NATURAL LANGUAGE") | NL → data records → deterministic engines. Journaled, Merkle-chained, revertable. |
| **D-220** | `surfaces/web` (Ω13): a third surface (after cli/mcp) serving the WorldModel + authoritative interpret/execute/consent over HTTP and a live journal/world stream over socket.io (path `/`). The browser replicates the WorldModel and runs nlcl-pure locally for instant typing feedback; execution is always the server's parse. | RATIFIED (owner: "as the user types there is instant interpreted feedback") | Local parse ≈ server parse because they share the same pure bytes (N1). |
| **D-221** | The sandbox runs the web surface via `mini-services/omega-engine` (launcher, port 3031, `bun --hot` — the sandbox service-folder law). The implementation lives in `surfaces/web` as a first-class surface; the launcher is a thin entry that imports it. | RATIFIED (sandbox constraint + architecture) | The Ω repo keeps its surface; the sandbox keeps its deployment law. |
| **D-222** | Email pack + provider v0.2.0: add CONTRACT `message.receive@1` (READ — ingestion is vault-internal; the simulator semantics are documented) + provider handler + frames. Enables the "when Peter messages me" rule loop. | RATIFIED (owner example, verbatim: "send this to Peter" / rules) | Contract addition on the pack is append-only (0.1.0→0.2.0); existing 1.x deps unaffected. |
| **D-300** | CDP transport is Bun-native `WebSocket` + `fetch`; no CDP client library is adopted. | **RATIFIED** | Continues D-211's zero-runtime-dependency law. |
| **D-301** | `provider-io-browser` v1 supports `attach` mode only; `launch` mode is deferred. | **RATIFIED** | Avoids per-OS process-lifecycle and packaging work before the observation/action substrate itself is proven. |
| **D-302** | Provider activation uses recipe recompile + atomic pin swap (D-213's mechanism); no new router/selector plugin is built. | **RATIFIED** | Mechanism already exists and is tested; a parallel selection layer would create two ways to change what serves an op. |
| **D-303** | Field-level mapping confidence (§9.2) is a candidate-ranking signal only; it never gates promotion. | **RATIFIED** | Preserves Ω8's "promotion is proof, not confidence" invariant — stricter than the DB track's own rule; this build keeps the stricter one. |
| **D-304** | Monkey-patch instrumentation (§7.2.1) is rebuilt natively, not adopted from any third-party interceptor library. | **RATIFIED** | Sidesteps license review entirely by not vendoring code. |
| **D-305** | Protocol/stream inference is reimplemented as small pure functions (§9.3), not ported from any GPL-licensed library. | **RATIFIED** | Algorithm concepts reimplemented natively; no code copied; keeps zero-new-dependency law intact. |
| **D-306** | `ProviderClass` (§5.1) is typed to admit a fourth member (e.g., `INTELLIGENCE_HARNESS`) without a breaking change, but that member is not added and no harness provider is built in Ω14–16. | **RATIFIED** | The DB track operates a real, working LLM-serving harness that will eventually need a provider class of its own; reserving the type now avoids a breaking change later, without pulling DB-track scope into this wave. |
| **D-307** | The realization-status vocabulary (Part 3) and the confidence-vs-proof distinction (constraint 6, Part 2) are published as a standalone versioned contract (Gate G0) before Ω14.0, and become the vocabulary the DB track's control-plane conforms to going forward. | **RATIFIED** | Two independently-evolving systems converging on the same "provider realization" concept risk hardening incompatible vocabularies; Omega's version is the reference. |
| **D-308** | `Variation` contract added (`contracts/src/variation.ts`); mapping gains additive `discovery.variations@1` grouping candidates by contractId (best-pick `discovery.map@1` output untouched). Multiple variations may be co-PROMOTED; routing preference is `vivim.law` policy. | **RATIFIED** | Toolbar button and keyboard shortcut for the same op are concurrently-valid realizations, not competing candidates; alternatives graduate to status-carrying entities. |
| **D-309** | Ω Control Plane v0: `AgentIdentity`/`BehaviorContract`/`DecisionRecord` (`contracts/src/agent.ts`) + `plugins/vivim-agent` (spawn/describe/propose/promote/rollback/decision). Reuses `LifecycleState`, vendored scope algebra, `Outcome<T>` from day one — no new token-minting or state-vocabulary machinery. | **RATIFIED** | Smallest working vertical slice for a persistent, permissioned, lineage-tracked agent, gated the same way every other Ω wave is gated. |
| **D-310** | `BehaviorContract.forbiddenActions` enforced by a per-principal overlay table inside `vivim.law` (`law.forbidden.set@1`), checked first in `law.check@1`. Capability scope and forbidden policy stay separate checks through the one gate. | **RATIFIED** | Reusing the one gate every mutation already passes through avoids a second host-invisible choke point; memory-only overlay, recipe amendment stays the durable path. |
| **D-311** | Perception node-kind union widened by exactly what `Variation.channel` demands (`menu`, `menu-item`), each backed by the `webmail-menu` capture fixture — not by a speculative full ontology. | **RATIFIED** | An unfixtured node kind is an unverified claim about application shape; evidence-before-authority applies to the ontology itself. |
| **D-312** | `Outcome<T>` (`contracts/src/outcome.ts`) used from day one on every new op for expected-but-negative results; thrown exceptions reserved for genuinely unexpected failures. | **RATIFIED** | Extends the existing `REFUSED`/`BUDGET` refusal-register pattern into plugin-level ops consistently, shaped by actual return needs rather than retrofitted. |
| **D-313** | Agent runtime fork: acting loop (B1a-first, evidence over debate) vs descriptive records. Detail: `docs/decisions/D-313-agent-runtime.md`. | **PROPOSED** | Machinery that looks alive is the worst outcome; B1a produces evidence for the fork. |
| **D-314** | DB-track conformance: human-attested checklist now, fixture test only when both sides publish. Detail: `docs/decisions/D-314-db-conformance.md`. | **PROPOSED** | Checklist costs nothing; shared packages couple irreversibly — sequence strength with evidence availability. |
| **D-315** | Live-agent quarantine semantics (finish vs halt vs migrate): process rule decided (blocker on shipping past fixture-replay), semantic TBD during B1a. Detail: `docs/decisions/D-315-quarantine-semantics.md`. | **PROPOSED** | Writing the code with the question live reveals which answer the invariant needs. |
| **D-316** | Composition flagship question deferred until the W1 conformance net ships and reports. Detail: `docs/decisions/D-316-composition-flagship.md`. | **PROPOSED** | The net serves either answer; resolving first buys nothing. |
| **D-317** | Test-lane sharding trigger is test count (~700), not wall clock. Detail: `docs/decisions/D-317-test-budget.md`. | **PROPOSED** | Count is machine-independent; clocks punish slow boxes and reward test deletion. |
| **D-318** | Phase A placement: extend `discovery-mind.json` (verification already lives there) over a new `providers.json`. Detail: `docs/decisions/D-318-phase-a-placement.md`. | **PROPOSED** | Reversal cost is one moved entry; confirmation is low-ceremony. |
